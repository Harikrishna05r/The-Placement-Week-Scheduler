The Problem

High Demand, Strict Capacities & Live Chaos

1. Capacity Over-Subscription

3,627 shortlist requests compete for only 2,560 physical room-slots across 4 days. Infeasibility is inevitable and demands intelligent priority-tier allocation.

2. Hard Concurrency Constraints

Top candidates receive up to 27 concurrent shortlists. The system must guarantee zero double-bookings while respecting room and interviewer panel limits.

3. Live Operational Disruptions

Companies arrive hours late, interviewers drop panels, and students withdraw. Re-solving naively causes chaotic schedule reshuffling.

4. Diagnostic Opacity

Standard schedulers fail with generic errors. Coordinators need exact binding constraint root causes (room, panel, student conflict).

Architecture

Full-Stack System Design

Backend: FastAPI + OR-Tools

  • Generator: Power-law shortlist distribution correlated with CGPA.
  • Solver: CP-SAT optional interval variables with cumulative tracks.
  • Infeasibility: explain.py hierarchical constraint analyzer.
  • Replanner: Disturbance penalty ($P=50$) with locked assignments.

Frontend: React 18 + Tailwind v4

  • Gantt Matrix: Room-by-time timeline with priority tier gradients.
  • Infeasibility Panel: Real-time triage with filterable badges.
  • Diff Approval: Pre-commit review modal preventing visual churn.
  • Search: Instant filtering across room, company, and student.
